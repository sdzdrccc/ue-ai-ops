# 08 · 动画资产与跨骨架重定向（★ 判据 + 脚本化全流程）

> ★ **什么时候翻这篇**：要换角色模型、要复用/批量搬动作库、要把两套骨架接起来（IK Retargeter）、
> 要用脚本改动画关键帧、或者**要判定「这个动作包能不能直接用」**的时候。
>
> ★ 本篇只写**操作层**：怎么判 · 怎么接 · 怎么用脚本落地 · 哪条路走不通。
> ★ 具体某个动画节点的参数含义属 API 层，★ 不在此文范围（见 `SKILL.md` §0）。

---

## 1. ★★ 判「动作能不能复用」看**骨架**，不看模型

★ **判据**：换角色模型之后动作能不能搬，取决于**骨架资产**的四件事 ——
**骨头名 ＋ 父子层级 ＋ 绑定姿势的朝向 ＋ 关节位置**。与「模型是不是新建的」无关。

| 情况 | 能不能直接用 | 做法 |
|---|---|---|
| ★ 同一份骨架资产（新网格重新绑到它上面） | ★ **能，零成本** | 导入时选"绑定到已有骨架"，动作一条不改 |
| ★ 不同骨架但**同构**（同名 · 同层级 · 同朝向，只关节位置不同） | ★ 能 | IK Retargeter **批量**重定向一次（§5） |
| ★ 命名或朝向不符（外部来源的骨架） | ★ 不能 | 先配**一次**链条映射，之后同来源的都按它批量 |

★★ **推论（最重要的一条）**：**永远让模型迁就骨架，★ 别让骨架迁就新模型。**
★ 骨架一动，挂在它上面的**全部**动作资产一起报废或错位；★ 模型只是个网格，重绑最便宜。

★ **一秒判读法**（判外部动作包能不能用）：

```bash
# 看骨头名是不是目标引擎的通用命名 —— 命中即"可能同构"，零命中就别买了
strings <file.fbx> | grep -E "^(pelvis|spine_0|thigh_|clavicle_|clavicle_l|clavicle_r)" | sort -u
```

★ **来源**：实测（对一个商场下载的动作包与两份自制骨架做比对，命名差异是唯一的阻断项）。

## 2. ★ 男女/多体型：两种骨架策略，**选一条，别混**

| 策略 | 做法 | 代价 |
|---|---|---|
| ★ **多套同构骨架** | 每套体型一套骨架（比例自由），动作库**批量重定向**一份给另一套；以后加动作再批一次 | ★ 每批新动作都要多跑一次批处理 |
| ★ **共用一套骨架** | 关节位置完全相同，动作**完全通用** | ★ 身体比例被锁死（同一个骨架，只能靠缩放网格） |

★ **判据**：**省事选共用，自由选同构**。★ 两者的动作复用性**都成立**，区别只在「以后每批动作的额外工序」。
★ **别做第三种**：两套骨架**不同构**却想互通 —— 那等于每条动作都要人手工调一遍。

---

## 3. ★★ 动作库四条约定（★ 换模型能整批搬走的前提）

1. ★ **只打一套骨架** —— 动作只对骨架负责，不对模型负责（§1）。
2. ★ **按动作命名，不带角色名** —— `AS_<动作>_<变体>`（如 `AS_Meditate_Loop`），
   ★ 不要 `AS_<角色名>_<动作>`：带角色名的动作库，换角色时**每条都要改引用**。
3. ★ **全部原地** —— 位移只写在 `pelvis`，`root` **一帧都不动**。
   ★ 勾了 Root Motion 的包，搬到别的角色/别的移动方案上会**双倍位移**或**漂移**。
4. ★ **循环动作首尾帧完全相同**；一次性动作（起跳/受击/死亡）要有**干净的起止姿势**
   （起止姿势不干净 ⇒ 混合时可见"抽一下"）。

★ **来源**：实测（一次"把动作库从旧骨架整批搬到新骨架"的实操，四条任一条不满足都要返工）。

## 4. ★ 手 K vs 买动作包：**复用性完全等价**

★ 两者都只是**挂在骨架上的资产**（§1），差别只在**当下投入**与**质量**。
★ **最划算的是静止姿势类**（打坐 / 持物 / 死亡 / 捧卷）—— 不需要时序、不需要物理、一次成。
★ **最不划算的是手 K 走跑打** —— 时序与重心转移的细节量，人工成本远高于买。

★★ **两条授权判据**（买之前先看，别看功能）：
- ★ **视频/照片转动作**这类工具，底层多为**研究授权的姿态估计模型** ⇒ **商用需另购**；
  且它只做"重定向/驱动"，**不生成动作** ⇒ 纯为两段动作搭一整套环境不划算。
- ★ 动作包要看清许可是否允许**在游戏内使用**（有些只允许"演示/学习"）。

## 5. ★★ IK Retargeter 全流程可脚本化（★ 不用点编辑器）

★ **整条链都能用 Python 建**，顺序如下（★ 工具输出实测）：

```text
① 建 IK Rig 定义         unreal.IKRigDefinitionFactory.create_new_ik_rig_asset(路径, 名)
② 拿控制器               unreal.IKRigController.get_controller(rig)
   ├ set_skeletal_mesh(rig, 网格)      —— 源、目标各建一份
   ├ set_retarget_root(rig, 根骨)
   └ add_retarget_chain("链名", 起骨, 终骨, goal)
      ★★ 两边链名必须一致 —— 源里叫 "LeftArm"，目标里也得叫 "LeftArm"
③ 建 Retargeter          unreal.IKRetargeterController.set_ik_rig(SOURCE/TARGET, rig)
   └ add_default_ops()                  —— 先铺一遍默认算子
④ ★★ 对齐（必做）        auto_align_all_bones(TARGET)
⑤ 批量出片               unreal.IKRetargetBatchOperation.run_batch_retarget(输入结构)
   └ assets_to_retarget 要 AssetData：unreal.EditorAssetLibrary.find_asset_data(路径)
```

★★ **第 ④ 步是最容易漏、后果最大的一步**：两套骨架的**静止朝向**不一致时，
只搬局部旋转会把四肢甩到身后 / 侧面（★ 而单看一两帧静止画面**可能看不出**）。
★ `auto_align_all_bones` 就是"把目标骨架静止姿态与源骨架对齐"的那一步。

★ **两个已知的"设不上"**：5.8 里 `b_include_referenced_assets` /
`b_overwrite_existing_files` 这两个属性名设了会 warning，★ **不影响结果**（别把它当失败）。
★ **来源**：实测（编辑器工具输出 ＋ 成品动作读回）。

## 6. ★★ 重定向产物要**分步改、每步落盘、再重新评估**

★★ **错误姿势**：把「改骨盆」和「算手臂 IK」写在同一次计算里，用同一个旧 pose。

★ **为什么错**：手臂 IK 的目标是挂在躯干上的 —— 骨盆一动，肩的位置就变了；
★ 拿旧 pose 算手臂，手臂会按**旧骨盆朝向**解，姿势看着"差不多"，其实是错的。

★ **正确顺序**：

```text
写 pelvis → 保存 → 重新取 pose → 再算手臂 IK → 再保存
```

★ **判据**：任何"多段改动"的姿势，**下一段必须基于上一段落盘后的 pose**；
★ 退出码全绿不能证明姿势对（§4·8），★ 要看**读回的骨骼世界坐标**。

## 7. ★★ 「姿势看着对但四肢不对」：正解不是反复调重定向参数

★ **实测症状**：重定向出来的动画，整体朝向对、躯干对，但**手臂/腿**明显不在源动作的位置上。

★ **两条正解（按成本排序）**：
1. ★ **抄「已知良好姿态」**：从**同骨架**的现成动画（待机之类）里，把相关骨骼的**局部旋转整套**搬过来。
   ★★ **抄上体时骨盆也要一起抄** —— 骨盆的 roll/twist 由源动画带来，
   ★ 只抄脊椎会得到"上身立直了、头还在栽"的怪姿势。
2. ★ **需要贴到某个位置的肢体，用两段 IK 解**，再写回关键帧（§6 的分步纪律）。

★★ **先量可达性，再定姿势目标**：目标角色的**臂长可能短于**「肩→目标点」的距离
（例：手臂总长 47cm vs 需要 58cm）⇒ ★ 手**够不到**，硬解只会把手臂拉直 / 穿模。
★ 做法：**先把骨骼长度量出来**（每根骨的变换差），再决定"手该落在哪"。

## 8. ★★ Python 改动画数据：可读可写，不用 Control Rig / 不用点编辑器

| 要做的事 | API（实测名） | 注意 |
|---|---|---|
| 写关键帧 | `anim.controller`（`AnimationDataController`）→ `set_bone_track_keys(bone, pos[], quat[], scale[], …)` | ★ **键数必须等于帧数**；★ **轨道必须已存在**（先建轨再加键） |
| 读某帧姿态 | `anim.get_anim_pose_at_frame(frame, unreal.AnimPoseEvaluationOptions())` | ★ **返回 pose（它是返回值，不是传进去的 out 参数）** |
| 取骨骼姿态 | `unreal.AnimPoseExtensions.get_bone_pose(pose, bone, space)` | ★ `space` **只有 LOCAL / WORLD**（没有 COMPONENT） |
| 改姿态后写回 | 取 pose → 改 → 写回序列 | ★ 写回前先确认轨道存在（同第一行） |

★ **两个类型坑**：
- ★ `unreal.Transform.rotation` 是 **Quat**，不是 Rotator ⇒ ★ **别喂给 `conv_rotator_to_quaternion`**。
- ★ 姿态里取出的变换要按 **LOCAL** 写回关键帧；用 WORLD 值直接写进局部轨道 = 姿势全歪。

★ **来源**：实测（一次"把待机动画的上体搬进另一段动作"的落地，全部在无头脚本里完成）。

## 9. ★★ 没有动画蓝图时的退路：单节点动画

★ **可用**（实测于 5.8），适合"一个动作演完再切回"的场景（打坐、施法吟唱、待机）：

| 动作 | API | 注意 |
|---|---|---|
| 直接播一段 | `USkeletalMeshComponent::PlayAnimation(asset, bLooping)` | ★ 5.8 是**两参**（asset, bLooping） |
| 混合空间取某位置 | `UAnimSingleNodeInstance::SetBlendSpacePosition(...)` | ★ **没有** `SetBlendSpaceInput` 这个名字 |
| 判"当前播的是不是它" | `GetCurrentAsset()` | 用来做进/出状态的幂等判断 |
| 判"播完了没有" | `IsPlaying()` | ★ 单段播完 **要自己切回**默认态 |

★★ **一个常见的资产缺陷**：演示用的动画蓝图**可能没有独立的「落地」段** ⇒
落地时看起来播了两次，而物理只落一次。
★ **判据**：数 `Landed` 的调用次数 —— **一次跳跃只该 +1**。
★ 这时改**代码驱动**（走跑用混合空间 ＋ 起跳/下落/落地三段）最省事。

## 10. ★ 在编辑器里新建「动画序列」的路径（★ 内容浏览器里没有）

★ `UAnimSequenceFactory::ShouldShowInNewMenu()` 返回 **false** ⇒
★ **「内容浏览器 → 新建 → 动画」里没有「动画序列」这一项**。

★ **正路**：在 **Persona**（打开骨架后）工具栏 **「创建资产 (Create Asset)」→ 动画 → 创建动画 → 参考姿势**。
★ 建完默认落在**骨架同目录**，★ 要自己挪。

★ **Persona 里两个不含糊的细节**（实测）：
- ★ 这版**没有「自动关键帧」开关** ⇒ 改序列长度要 **右键时间轴 → 序列编辑 → 在序列末尾追加帧**
  （★ 拖时间轴的把手改的是**播放范围**，不是序列长度）。
- ★ 打帧 = 工具栏「关键帧」按钮或快捷键 `S`，★ **只对当前选中的骨骼生效**；
  ★ 没打帧的骨头会一直停在**绑定姿势**（所以"只动了一根骨头"的动画要么补满，要么用脚本批量写）。

## 11. ★★ 出引擎进 Blender：**骨骼尾巴朝向不可信**

★ **实测**：UE 导出的骨骼进 Blender 后，导入器会按**它自己的约定**猜骨长/朝向
（UE 骨骼沿 X，Blender 的假设多为沿 Y）⇒ 按"世界方向对准"或"叠局部旋转"摆姿势，角色会被拧歪。

★★ **最坑的一点**：`pose = rest` 时**不形变** ⇒ **静止渲染看起来完全正常**，
★ 骨架已经是错的，但你要到摆第一个姿势才发现。

★ **判据（两条）**：
1. ★ **先渲一张静止姿势核对骨架**（骨头方向对不对），再动手摆。
2. ★ 真要做，只有两条路：**重建骨架 ＋ 重绑**，或**别走这条（换用引擎内工具）**。

★ **来源**：实测（两次尝试，均在"静止渲染正常、一动就歪"上浪费时间）。

## 12. ★ 官方工具集在动画这块的边界（★ 别承诺做不到的事）

| 想要 | 官方工具有没有 | 替代 |
|---|---|---|
| 导出/导入 FBX | ★ **有**（Sequencer 的 `export_fbx` / `import_fbx` / `export_anim_sequence`） | —— |
| 查询骨骼网格（骨名/LOD/顶点/morph/socket） | ★ **有** | —— |
| **生成动作** | ★ **没有** | ★ 手工 K、外部工具、或脚本改关键帧（§8） |
| **改动画蓝图 / 状态机** | ★ **没有**（图编辑只认**事件图与函数图**） | ★ 代码驱动动画，或人手工连线 |
| **从内容浏览器建动画序列** | ★ 走 Persona（§10） | —— |

★★ **操作含义**：★ **别规划"用 MCP 自动搭一套动画状态机"** —— 这条能力不存在。
★ 要么**代码驱动**（`PlayAnimation` / 单节点 / 状态由 C++ 管），★ 要么**人手工连**一次。
★ 详见 `05` §6·4。
