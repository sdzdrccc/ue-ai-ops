# 03 · UMG 界面与资产（★ 架构判据 + 落盘根因）

> ★ 本文讲★ **界面代码怎么组织**、★ **资产类操作为什么会「改了没生效」**。

---

## 1. ★★ 核心架构判据：WBP 只做布局

> ★★ **WBP（Widget Blueprint）只负责「控件的位置、尺寸、层级、名字」；
> ★ 逻辑、静态文案、样式值、事件绑定 ★ 全部放 C++。**

| 放哪 | 具体内容 |
|---|---|
| ★ **WBP** | 控件布局 · 控件**名字**（C++ 按名字取） |
| ★ **C++** | ★ 静态文案 · ★ 颜色/尺寸常量 · `OnClicked` 等事件 · 数据显示与填充 · 提示条内容 |

### 1.1 ★ 为什么样式值必须放 C++

★ **亲历的三种返工**：

| 返工 | 表现 |
|---|---|
| ★ **「两处都写」** | 同一个颜色在 C++ 和 WBP 各写一遍 ⇒ ★ 改了一处忘了另一处 ⇒ ★ 长期不一致 |
| ★ **「资产里改不到 / 改不持久」** | ★ 见 §3 ⇒ ★ 最后只能改 C++，等于白在资产里试 |
| ★ **「无法 review」** | ★ 样式值在二进制资产里 ⇒ ★ **代码 review 看不见、回归测试跑不到** |

★ **推论**：★ **凡是「每个项目都要、且要能 review」的东西 ⇒ 放代码；★ 凡是「每个项目都不一样、且靠美术手感」的东西 ⇒ 放资产。**

### 1.2 ★ 绑定写法

| 写法 | 行为 | ★ 建议 |
|---|---|---|
| ★ `BindWidget` | ★ 找不到该控件 ⇒ **直接加载失败** | ✗ **不用**（★ 会毁掉「C++ 当空壳跑流程」的退路） |
| ★ `BindWidgetOptional` | 找不到 ⇒ **置 null，不报错** | ✅ **用这个**（★ 功能照走，缺控件只影响那一处） |

★ **事件绑定**：★ 用普通委托（`AddDynamic` / `AddUObject`）——
★ **不要用 UMG 的 Property Binding**（★ 那是蓝图里把属性拖成绑定 / C++ 里每帧反射取值）。

★ **判定命令**（搜到即违规，`BindWidget` 本身不算）：
```bash
grep -rnE "Bind\(&|CreateBinding|PropertyBinding" <Module>/Private/UI/
```

★ **自查小技巧**：★ 在 C++ 里留一条**启动日志**，逐个打印绑定是否成功 ——
★ 「控件没接上」是静默的（不崩、只是没效果），★ **日志能把它变成可见的**。

## 2. ★ 改 WBP 之前：先拿真源

★ **两种错误做法**：
| ✗ 做法 | 为什么错 |
|---|---|
| ★ **猜控件名** | 猜错 ⇒ 绑定为 null ⇒ ★ **静默无效果**，你以为是代码问题 |
| ★ ★ **直接 grep 资产二进制** | ★ **资产里有多张名字表**（图节点、控件、资源…）⇒ ★ **grep 只能命中其中一张** ⇒ ★ 会得出「资产是空的」这种★ **完全错误的结论**（★ 实测栽过） |

★ **正确做法**：★ **用编辑器工具读控件树**（不同客户端工具名不同，功能都是「读当前资产的结构」）：
```
选中资产 → 设为目标 → 读控件树
```
★ 拿到 ★ **真实控件名 + 层级 + 类型**，★ 再决定对齐方向。

### 2.1 ★ 对齐方向：先定一条，别混

| 方向 | 做法 | 何时选 |
|---|---|---|
| ★ **改代码对齐资产** | 保留 WBP，把 C++ 的绑定名改成与它一致 | ★ **资产已经做得不错**（★ 风险最低：资产不动） |
| 改资产对齐代码 | 重命名 WBP 控件 | ★ 代码名已对外（文档/团队约定），★ 且资产改动可控 |

★ **代价意识**：★ 改资产名可能**破坏已有布局与绑定** ⇒ ★ 改之前先备份/提交。

★ **混合方案**（两头都不放弃）：★ 代码里做一层**名字映射**（新名 → 旧名）——
★ 优点是两边名字都保住；★ 缺点是多一层映射、后续维护要记两套名。

## 3. ★★★ 「改了不落盘」：根因与修法

### 3.1 现象

★ **MCP 改控件属性** ⇒ 接口返回成功 ⇒ **立刻读回也对** ⇒ ★ **但资产文件 mtime 不动** ⇒ 关掉重开就丢了。

### 3.2 ★ 根因：三个调用分管三件事，前两个不管落盘

| 调用 | 作用 | 管落盘 |
|---|---|---|
| `Modify()` | ★ **撤销栈**（能不能 Ctrl+Z 退回） | ✗ |
| `MarkBlueprintAsStructurallyModified` | ★ 「蓝图变了，要重编译」 | ✗ |
| ★ `MarkPackageDirty()` | ★ 「这个包有未保存改动」 | ★ **这才是** |
| ★ 保存（如 `PromptForCheckoutAndSave`） | ★ **写磁盘** | ★ **这才是** |

★ **典型缺陷写法**：
```
写入属性 ✅
MarkBlueprintAsStructurallyModified ✅      ← 只管重编译
return success                                ← ★ 没标脏、没保存 ⇒ 调用方误以为「成功 = 已存」
```

### 3.3 ★ 修法（两层都要）

| 层 | 加什么 | 效果 |
|---|---|---|
| ★ **资产层** | 写操作后 `MarkPackageDirty()` | ★ 编辑器知道「有未保存改动」 |
| ★ **调用层** | 成功后**显式保存** | ★ **当场写磁盘**（★ 这才叫「改了就在」） |

★ **只加资产层不够** —— ★ **用户关掉编辑器照样丢。**

★ **关于「会不会弹窗」**：★ 保存接口常有多个参数控制（是否提示、是否可取消）——
★ **无人值守场景要显式关掉交互**，否则会卡在一个模态框上。

### 3.4 ★ 一分钟自查

```
改一个属性 → 立刻看资产文件的 mtime
   变了 ⇒ 落盘正常 ✔
   没变 ⇒ ★ 写入路径缺标脏/缺保存
```

★ **建议把这个检查写成一个脚本**（见 `../scripts/`）—— ★ **它能挡掉「以为成功了」这类静默失败**。

## 3·5、★★★ 几十个控件要改时：★ headless 批处理，别在编辑器里手点

★ 一次要改几十个控件（★ 批量套几何、批量改名、批量灌样式）⇒ ★ **逐个在编辑器里改 = 慢 + 不可复跑 + 会漏**。

### 3·5·1 ★ 姿势

```
★ 先导出一份「几何真源」（★ 样式/坐标从别处来，别手抄）
        ↓
★ 用无头编辑器跑一个脚本：读真源 → 逐控件灌值 → 标脏 + 保存
        ↓
★ 判据：脚本自己打印 ok=N fail=M   ★ M≠0 就当失败处理，别只看「跑完了」
```

★ **命令行形态**（★ 无需开着编辑器界面）：
```bash
<Engine>/Binaries/<Platform>/UnrealEditor-Cmd.exe <Project>.uproject \
  -run=pythonscript -script=<repo>/tools/<apply>.py \
  -stdout -unattended -nosplash -nullrhi
```
★ 关键参数：`★ -stdout`（★ **日志进 stdout，否则你什么都看不见**）· ★ `-nullrhi`（★ 不建渲染设备）· ★ `-unattended`（★ 不弹窗）。

### 3·5·2 ★★★ 写完必须「读回来」

★★ **本条是这一节的核心**，★ 也是最容易省掉、代价最大的一条：

> ★ **「设置属性的调用返回成功」≠「值真的写进去了」。**

★ 实测过的静默失效：**给一个不支持该属性的槽位设置它 ⇒ 返回成功、实际没写**。
★ 通用形态：★ **调用方只管「设了」，没人回读「到底生效没」**。

| # | 纪律 | 做法 |
|---|---|---|
| 1 | ★ **设完立刻读回** | ★ 同一个对象把属性读出来，比对；★ 不等就当没设 |
| 2 | ★ **数量对不上就失败** | ★ 打印 `ok / fail`；★ ★ **`fail≠0` ⇒ 整批算失败**（★ 别只看「跑完了」） |
| 3 | ★ **留几何证据** | ★ 改完**截图或量一次边距**（★ 「看着对」不算，见 §3·5·3） |

### 3·5·3 ★★ 两个「量出来才知道」的坑

| 坑 | 现象 | ★ 怎么抓 |
|---|---|---|
| ★ **渲染器裁掉一圈** | ★ 截图里底部/右侧少一截 | ★ ★ **截图尺寸 ≠ 视口尺寸**（★ 窗口边框/工具栏会吃掉一部分）⇒ ★ **要么显式设视口，要么截完按已知比例裁** |
| ★ **背景骗过自动测量** | ★ 量「卡片宽度」量出一个含背景的巨型数字 | ★ ★ **紧裁到元素边界再量**；★ ★ **带花纹/渐变的背景不能参与判边** |

★★ **这两条的共同教训**：
> ★ **自动测量只能量「边界干净的东西」。**
> ★ 一旦测量对象周围有装饰、背景、边框，★ **量出来的数一定偏向「包含它们的那个整体」**。

### 3·5·4 ★ headless 的四个坑（★ 实测，详见 `07`）

| 坑 | 症状 | ★ 避 |
|---|---|---|
| ★ 日志不落盘 | ★ 脚本 print 了但什么都没收到 | ★ 加 `-stdout` |
| ★ 输出被管道掐断 | ★ 处理到一半就死（★ 像是脚本崩了） | ★ ★ **别把长输出直接管到 `head`**；★ 先重定向进文件再看 |
| ★ 资产树不可直接写 | ★ 脚本报权限/受保护错误 | ★ 走编辑器给的接口改，不直接改资产对象 |
| ★ 传 JSON 字符串当参数 | ★ 参数被当成本体类型解析失败 | ★ **命令行传 JSON 要显式声明成字符串** |

★ **第 2 条特别阴**：★ **`head` 之类的工具提前关管道 ⇒ 读端一关 ⇒ 写进程被信号杀掉** ——
★ 表现像「脚本跑到一半崩了」，★ 实则是**你自己掐死了自己**。

## 4. 界面的其它常见决策

| 决策点 | 建议 | 理由 |
|---|---|---|
| ★ **要不要用 CommonUI** | ★ **界面少、单端输入时不要用** | 它为「面板堆栈 + 多端输入路由」而生 ⇒ 界面少时是过度设计 |
| ★ **要不要 WebUI（CEF）** | ★ **先别用** | 能 1:1 还原设计稿，但增包体/内存，★ 且有合规与性能成本 |
| ★ **渐变/模糊/外发光** | ★ **纯色降级优先**，真要效果再上材质 | ★ 渐变在 UI 里常用「贴图」实现 ⇒ ★ 没有美术资源时纯色最省 |
| ★ **固定比例适配** | ★ 设计期按目标分辨率写死，★ 运行时用等比缩放容器 | 避免「一堆绝对坐标在不同分辨率下全错位」 |
| ★ **字体** | ★ 先用引擎默认，★ 留好换装口子 | ★ 字体资源常缺；★ **字号全部走常量**，换字体只改一处 |

★ **共同点**：★ **以上都能「先降级、后补齐」** ⇒ ★ 别在资源没到位时卡住不动。
